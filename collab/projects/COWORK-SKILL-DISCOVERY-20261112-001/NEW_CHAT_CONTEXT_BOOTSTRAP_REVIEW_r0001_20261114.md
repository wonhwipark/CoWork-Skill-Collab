## 4. 최신성과 중복을 줄이는 작성 규칙 (개선안)

1. **CURRENT 첫 ## 절은 현재 요약**, 그 아래 이력은 날짜별 보존으로 통일한다. 최신/다음 조치·근거 수준·현재 점검·후속 조건을 명시.
2. TRACKER의 기존 schema/phase를 재사용한다. 독립 리뷰 NOT_RUN, 미실행 후속 등을 임의 PASS 또는 BLOCKED로 변환하지 않음.
3. 브리프에는 작성/확인 시각, 출처 CURRENT 링크와 고정 참조를 붙인다. 출처 변경 이후 만들어지지 않은 요약은 오래됐음을 표시하고 CURRENT를 재확인.
4. 1차 최소 적용은 같은 문서 업데이트 작업에서 브리프의 관련 줄만 함께 갱신하는 방식. 별도 LLM·감시기·네트워크 호출이 필요하지 않음.
5. 수동 갱신 누락이 실제로 반복되면 기존 문서/대시보드 생성기 재사용 가능성을 먼저 검토. 그때만 얇은 결정형 요약 생성·경로/정본 검증을 최소 보완. 새 스키마·상태 DB를 기본 도입하지 않음.
6. 회사 코드/사진·로그·상세 MSC/비밀·미승인 PRIVATE 원문을 브리프나 PUBLIC에 복제하지 않음. 원본은 권한 내 참조.
7. 최초 요약은 확인된 자료만 작성. 새 버전 번호·리뷰 PASS·자동 실행을 추정하지 않음.
8. 이미 보고된 G0/기존 자체시험은 증거 수준에 맞게 재사용하고, 미확인 또는 변경분만 조사. 이후 보고가 들어오면 그 항목만 갱신.

## 5. 자동 파악의 실제 범위

GitHub 문서만 추가해서 프로젝트 설정·다른 창의 지침·자동 문서 호출이 바뀌었다고 보고하지 않는다.

제안하는 프로젝트 시작 지시 예:

> CoWork 작업은 GitHub PRIVATE wonhwipark/CoWork-Skill-Collab의 main에서 collab/CONTEXT_BRIEF.md를 먼저 읽고, 요청에 해당하는 CURRENT와 열린 메모를 확인한 다음 기존 스킬을 재사용해 진행한다. 브리프와 실제 최신 근거가 다르면 최신 근거를 따른다.

이 문구는 **제안 초안**이며 현재 존재하지 않는 브리프를 지금 읽으라고 지시하는 실행 프롬프트가 아니다. 브리프를 실제 생성·검증하고 진입 링크를 연결한 뒤에만 적용한다. 사용자 프로젝트 설정을 이 작업에서 변경하지 않았고, 위 지시를 읽는 세션에서도 실제 GitHub 조회 권한·도구가 있어야 한다.

즉 제안의 목표는 “한 파일을 읽으면 공통 맥락을 파악할 수 있게 함”이다. “사용자가 새 창을 열기만 하면 요청 없이 항상 백그라운드로 선조회됨”을 보장하는 자동화가 아니다.
