### 5-1. 로컬 전용 계약 프로토타입 (`local_only_contract_r0001`, 코드 없는 설계 증거)
GitHub에 올라가는 것은 **제어면 기록**뿐이다: 불투명 ID, **솔트 커밋먼트**(`SHA-256(도메인‖솔트‖산출물 다이제스트)`), 범위(LOCAL_ONLY), 정책 revision, 비용 상한, nonce, 발급·만료, repo ID, 서명 키 ID. **ZIP의 SHA-256·크기·이름·경로는 포함하지 않는다.** 솔트는 산출물과 함께 로컬 경로로만 전달되므로, 산출물과 솔트를 가진 쪽만 일치를 증명할 수 있다. 승인은 승인자 Ed25519 서명, 영수증은 **리뷰어가 별도 키로 서명**하며 리뷰 원문 대신 **원문의 다이제스트**와 판정·건수만 담는다.
- 시험 **19개 PASS**(합성 키): 커밋먼트는 다이제스트와 다르고 솔트 없이 추측으로 확인 불가, 산출물·솔트 일치 시에만 로컬 결합 성립, 게시 기록에 다이제스트·크기·이름·경로가 없고 누출 검사가 값과 경로를 잡음, 허용 필드 외 추가 필드 거부, 필드 변경은 서명 오류, 신뢰하지 않는 키 거부, 만료·미발효 거부, nonce 재사용 거부, 영수증은 요청·커밋먼트가 같아야 하고 **EXTERNAL_API 리뷰어 주장 거부**, 승인자 자신의 리뷰 거부, 같은 요청의 두 번째 영수증 거부, 위조·알 수 없는 판정 거부. **변이 5종 전부 검출**(솔트 무시, 외부 API 허용, nonce·중복·서명 검증 제거).
- **증명하지 못하는 것**: 리뷰어가 실제로 온프레미스에서 실행됐는지는 서명된 **주장**(`ATTESTED_NOT_VERIFIED`)일 뿐이며 조직이 실행 환경을 별도로 검증해야 한다. GitHub의 커밋먼트·영수증 일치는 **소스 전체 무결성의 증명이 아니다**(원본은 원격에서 읽을 수 없다). 이 프로토타입은 운영 프로토콜이 아니며 **독립 보안 리뷰와 사용자 운영 승인 전에는 어떤 READY·REQUEST에도 연결하지 않는다**. 게시 가능 도구로 `tools/`에 신규 추가(상세 §8).

### 5-2. 로컬 독립 리뷰 경로(설계)
1. **LOCAL_ARTIFACT**: 원본 ZIP은 승인된 내부 호스트에만 봉인 보존, 바이트 검증은 로컬에서만.
2. **LOCAL_INDEPENDENT_REVIEW**: 개발 세션과 다른 리뷰어(사람 또는 **조직 승인된 온프레미스 모델**). 외부 API 전송 OFF 검증. 개발 세션 자체 시험은 독립 리뷰가 아니며 `INDEPENDENT_REVIEW=NOT_RUN` 유지. 리뷰 원문은 로컬 보존, GitHub에는 영수증(다이제스트·판정·건수)만.
3. **GITHUB_CONTROL_PLANE**: 위 §5-1 필드만. 새 문서가 서명된 승인 없이는 어떤 자동 리뷰도 트리거하지 않는다.
- **호스트 실측(이름만 확인)**: 이 PC에는 **로컬 모델 런타임이 없다**(Ollama·LM Studio·llama 계열·OpenCode·Roo 모두 없음, 모델 포트 미사용). 하드웨어는 NVIDIA GPU 1개, RAM 16GB로 소형 모델 수준이다. 조직이 승인한 온프레미스 모델이나 사람 리뷰어가 없으면 **`E=BLOCKED_LOCAL_REVIEWER`**. 외부 API Claude를 이 PC에서 실행하는 것은 반출과 동일하게 취급한다.

### 5-3. 이미 게시된 식별자에 대한 정직한 공개 (사용자 결정 필요)
이전 결과·CURRENT에는 후보 ZIP(v0.2.8·v0.2.10·v0.2.11)의 **원시 SHA-256과 크기**, 그리고 v0.1.5 유래 **파일 이름 일부**와 줄 수 통계가 PRIVATE GitHub에 이미 게시되어 있다. D2의 "SHA 자체가 내부 식별자라 제한될 수 있다"는 관점에서는 **소급 재점검 대상**이다. 이력 삭제·재작성은 파괴적이라 실행하지 않았다. 앞으로는 v0.2.12부터 원시 다이제스트·크기를 게시하지 않는다.

## 7. 남은 사용자 결정·입력 (최소 한 묶음, 대리 확정 없음)
1. **서명자 기기**: 실제 기기 종류(회사 관리 PC인지)와 키트 6개 파일의 내부 이동 허용 여부.
2. **토큰**: 기존 자격은 과권한으로 판정됨. 새 단일 저장소 Contents 읽기 전용 fine-grained 토큰을 **직접 발급할지**(발급·설치는 별도 승인) 또는 보류할지. 발급한다면 GitHub UI 8항목 O/X는 사용자 확인.
3. **로컬 독립 검토자**: 조직 승인된 온프레미스 모델 또는 사람 리뷰어가 있는지, 그리고 로컬 전용 프로토콜(§5-1) 변경과 독립 보안 리뷰 진행 승인 여부.
4. **LIVE 계정 구성**: LIVE 감시기를 현재처럼 운영자 계정으로 둘지, 별도 비관리자 서비스 계정으로 옮길지(후자는 운영 ACL 변경이며 별도 승인). 전자라면 C의 ACL 축은 LIVE에 적용되지 않는다.
5. **기게시 식별자**: §5-3의 이미 게시된 다이제스트·크기·파일명을 제한 대상으로 볼지.
LIVE 전환·E 비용·운영 키는 이 응답과 별개의 후속 승인이다.
