- 성격: 사용자가 이전부터 요청한 **기본 작성 규칙**을 반복 확인 없이 적용. 실제 설치·모델 호출·운영 변경을 승인하거나 실행하지 않는다.

## 기본 규칙

1. **실행용 프롬프트 본문에는 망·위치 구분 표현인 `사내`, `사외`, `내부망`, `외부망`을 기본적으로 쓰지 않는다.** 이 구분이 필요하다면 `실행 환경`, `협업 환경`, `대상 호스트`, `실행 호스트`, `작업 저장소`, `배포 저장소`, `현재 설치본`, `승인된 연결`처럼 역할/권한 중심으로 서술한다.
2. 사용자가 특정 망 구분을 프롬프트에서 **명시적으로 요청했거나**, 실질적 실행·보안 통제상 위치를 구분하지 않으면 오류가 발생하는 경우에만 좁은 예외를 허용한다. 예외가 필요하면 지리적 수식어보다 명시적 호스트/저장소/승인 정책의 실제 ID를 우선한다.
3. 실행용 프롬프트에서는 외부 협업 서비스 브랜드·URL·경로·토큰 또는 인증 의존성을 불필요하게 노출하지 않는다. 단 실제로 필요한 승인된 실행 계약의 정확한 경로/버전/Job ID는 보존한다.
4. **사외용 정책·상태 설명과 실행용 프롬프트를 구별한다.** 정책 문서에서 환경 역할을 설명하는 것과 실행 프롬프트 본문에 위치 수식어를 강제하는 것은 별개이다.
5. 요청을 재작성·수정하면 **기존 WritingBlock 전체를 같은 ID로 교체**하고, 신규 산출물에서 같은 표현이 재발하지 않도록 본문/제목/주석/결과 형식을 검토한다.
6. 이미 배포된 불변 ZIP이나 실행 이력은 문체 변경만을 이유로 자동 재게시·재실행하지 않는다. 다음 승인된 신규 버전/프롬프트부터 적용한다.
