## 1. 새 창·새 작업의 시작 순서 — 통합 브리프 적용 (2026-11-14)

1. PRIVATE `wonhwipark/CoWork-Skill-Collab`, branch `main`, [collab/CONTEXT_BRIEF.md](../../CONTEXT_BRIEF.md)를 먼저 읽는다. 협업 운용·L1 지식 방향·관리 스킬을 한 번에 파악한다.
2. 브리프의 요청별 경로에서 해당 CURRENT의 현재 요약·열린 메모·관련 최신 결과/영수증을 확인한다. source blob이 달라졌거나 내용이 충돌하면 해당 원문을 다시 읽고 최신 근거를 따른다.
3. 브리프에서 기존 스킬 후보를 고르고 상세 I/O가 필요하면 [기존 카탈로그](../../knowledge/SKILL_CAPABILITY_CATALOG.md)와 관련 SKILL/참조 계약만 확인한다. 스킬 이름을 사용자가 말할 때까지 기다리지 않는다.
4. 실제 작업에 적용되는 [START_HERE](../../START_HERE.md)의 계약과 승인 범위를 확인한다. 이미 유효하게 읽은 문서를 링크 순환 때문에 다시 읽지 않는다. 새 변경·근거 누락·위험 행위에 필요한 범위만 추가 확인한다.
5. 기존 기능과 요구를 비교해 REUSE/CONNECT/입증된 최소 EXTEND/DEFER를 남긴다. 미확인 CLI/API를 만들어 호출하지 않는다.
6. CURRENT·정책·카탈로그를 변경하는 작업은 브리프의 관련 요약·출처 blob·확인일도 같은 문서 갱신에 포함하거나 재확인 대상으로 표시한다.

단순 상태 질문은 브리프와 관련 CURRENT로 충분하면 답한다. 조회 2회를 강제 상한으로 두어 필수 근거를 생략하지 않으며, 반대로 18개 감사·전체 이력·모든 계약을 매번 재조사하지 않는다. 인증/조회가 막힌 부분만 추가 확인/BLOCKED로 분리하고 가능한 독립 작업은 계속한다.

## 2. 설계 전에 남길 재사용 판단

| 판단 | 사용할 때 | 기록할 내용 |
|---|---|---|
| REUSE | 기존 계약이 요청을 이미 충족 | 정확한 스킬·근거 위치·지원 입력/출력·제한 |
| CONNECT | 기존 기능은 있으나 호출/산출물 연결에 공백 | producer/consumer·입출력·승인·원장 소유자·실제 연결 gap |
| EXTEND | 원문/설치 계약을 확인해 실제 기능 gap이 입증됨 | 기존 제공자로 충족 불가한 이유·최소 변경·호환/시험 계획 |
| DEFER / ADDITIONAL_CHECK_REQUIRED / BLOCKED | 관련성·원본·권한·API가 미확인 | 미확인 내용·필요 근거·계속 가능한 작업 |

확인 전에는 EXTEND를 확정하지 않는다. 관련 스킬이 없다고 결론 내리기 전에 기존 목록과 원본을 탐색한다. 실제 부재와 이번 조회 실패를 구분한다. 짧은 변경은 간단한 표나 몇 문장으로 충분하며 새 Work/원장·schema·상시 감사 보고서를 만들 필요는 없다.

근거는 문서/패키지 원문/격리 시험/호스트 설치/실제 호출로 구별하고 날짜·버전·commit/허용된 원본 위치를 붙인다. 과거 감사·설계·자가 시험을 최신 설치 또는 독립 리뷰 PASS로 승격하지 않는다.

## 3. 현재 지식 설계에 적용할 경계

- code-analyzer는 분석 사실·근거, doc-converter는 기존 변환·표현 규칙을 우선 검토한다. 실제 역할·I/O는 설치 원문과 대조하며 Updater가 중복 구현하지 않도록 한다.
- Workflow/Kernel의 기존 Work 선택·원장·Evidence·export, Git/P4의 기존 source 고정 기능, Updater/기존 writer의 승인·revision·readback·복구 기능을 먼저 매핑한다.
- SourceSnapshot·CAS·N:M·복구는 요구를 설명하는 개념이다. 동일 이름의 새 API·record·엔진이 있어야 한다는 구현 지시가 아니다.
- G0 설치 사실과 G1 설계 가정을 분리한다. K5.8 재분류는 설계표만 작성하며 기존 Knowledge·metadata·registry/schema·Work/Evidence를 변경하지 않는다.
- 미확인 API/record는 ADDITIONAL_CHECK_REQUIRED 또는 BLOCKED. 신규 엔진/schema는 입증된 gap의 최소 범위 후속 설계로만 검토한다.
- 진행 중 PUBLIC r0005 인계와 수행 요청은 이 절차로 대체·취소·재실행하지 않는다. 열린 후속 메모는 결과가 들어온 다음 판정한다.

- START_HERE, 저장소 README, AGENTS, OPERATING_BASELINE은 같은 CONTEXT_BRIEF를 먼저 연결하고, 세부 스킬 목록·계약/CURRENT는 브리프에서 필요한 범위로 이동한다.

- 목록의 보강은 비민감 문서 범위에서 PRIVATE main에 직접 게시하고 원격 내용·commit·SHA-256을 검증한다. 민감 원문·내부 코드·MSC·로그·토큰은 PRIVATE에도 게시하지 않는다.
